# Audit UangKu, 25 November 2026

**Keputusan saat audit: tunda rilis untuk data keuangan pengguna.** Pada alur REST biasa, transaksi yang sah mendapat respons sukses meski tidak tercatat di PostgreSQL. Di perangkat, membatalkan pengeluaran tertentu tidak mengembalikan alokasi kantong ke nilai semula. Ada pula batas akses antarpengguna yang belum ditegakkan di server. Temuan dan nomor baris dalam tabel merekam keadaan sebelum perbaikan.

Audit ini mencakup worktree pada `54bf7b9` beserta perubahan lokal yang belum di-commit. Hasil uji memakai data sintetis. Temuan keamanan berasal dari pemeriksaan kode, bukan percobaan terhadap akun atau layanan nyata.

## Risiko lain yang terverifikasi dari kode

- **Satu struk dapat menahan transaksi lain.** Jika foto lokal tak lagi tersedia atau unggahan selalu gagal, seluruh batch dibatalkan sebelum push. Percobaan berikutnya membaca baris yang sama. Pisahkan kegagalan per transaksi dan tawarkan pemilihan ulang struk. [Antrean](../apps/mobile/src/sync/syncEngine.ts#L50-L75)
- **Berkas ekspor bisa tertinggal setelah penghapusan akun.** CSV dan `.ukbak` ditulis ke cache aplikasi; pembersihan akun menghapus direktori struk dan isi SQLite, bukan ekspor di cache. Pisahkan cache per pemilik dan bersihkan berkas sementara. Ini berbeda dari salinan yang sengaja disimpan pengguna di luar aplikasi. [Ekspor](../apps/mobile/app/(tabs)/settings.tsx#L246-L285), [pembersihan](../apps/mobile/src/auth/deleteAccount.ts#L3-L13)
- **Undangan kantong belum bekerja antarperangkat.** Layar mengajak teman bergabung, tetapi aksi gabung hanya mencari kantong di SQLite yang pemiliknya adalah pengguna aktif. Implementasikan alur server yang memeriksa keanggotaan atau jangan tawarkan undangan lintas akun dahulu. [Layar](../apps/mobile/app/pockets/index.tsx#L267-L285), [pencarian](../apps/mobile/src/db/sqlite.ts#L1899-L1915)
- **Form edit tidak menyimpan pilihan tanggal dan kantong.** Kontrolnya tetap aktif, tetapi kedua nilai tidak dikirim ke `updateLocalTransaction` sebelum notifikasi sukses. Simpan perubahan atau nonaktifkan kontrol yang belum didukung. [Form](../apps/mobile/app/transaction/new.tsx#L740-L767), [penyimpanan](../apps/mobile/app/transaction/new.tsx#L288-L309)
- **Periksa konfigurasi jika Compose ini dipakai untuk rilis.** PostgreSQL dipublikasikan ke host dengan kredensial tetap. Hanya data PostgreSQL yang mendapat volume; struk dengan driver lokal berada di lapisan tulis kontainer API dan dapat hilang ketika kontainer diganti. Batasi jaringan, gunakan rahasia per lingkungan, serta uji pemulihan struk dan database bersamaan. Ini temuan pada konfigurasi repo, bukan konfirmasi bahwa server produksi terekspos. [Compose](../docker-compose.yml#L5-L38), [penyimpanan struk](../apps/api/src/modules/storage/storage.service.ts#L51-L56)

## Peta aplikasi dan verifikasi

- **Alur utama:** Expo/React Native membaca dan menulis SQLite. Perubahan transaksi masuk ke antrean lokal, dikirim ke API Bun/Elysia, lalu disimpan di PostgreSQL lewat Drizzle. Paket `@uangku/contracts` menyediakan validasi dan utilitas bersama. REST transaksi dan sync masih memiliki implementasi penulisan yang berbeda.
- **Yang lulus:** 107 tes bawaan, 0 gagal; typecheck workspace `mobile`, `api`, dan `contracts`; build bundle API serta ekspor bundle Expo untuk iOS dan Android. Suite antara lain menguji retry saat konfirmasi sync hilang, batas bulan, privasi struk, dan penghapusan akun saat storage gagal.
- **Yang diuji terpisah:** respons REST dibandingkan dengan baris yang benar-benar tersimpan di PostgreSQL sementara. Perhitungan kantong, rekonsiliasi bank, ekspor-impor CSV, dan antrean dompet diperiksa melalui fungsi aplikasi dengan SQLite di memori. Angka contoh berasal dari hasil eksekusi tersebut.
- **Batas verifikasi:** Bun lokal 1.4.4, sedangkan CI menetapkan 1.3.14. Ekspor bundle bukan pengujian aplikasi native. Perangkat fisik, infrastruktur produksi, bucket eksternal, dan data pengguna tidak digunakan.

**Urutan perbaikan:** tutup akses lintas akun dan kegagalan kunci; pindahkan jalur penulisan REST ke penyimpanan transaksional; kemudian jadikan contoh angka pada temuan 05-08 sebagai tes regresi. Sebelum distribusi, uji siklus penuh pada dua perangkat: catat saat offline, sinkronkan, bandingkan saldo, lalu pastikan akun dan berkas sementaranya benar-benar terhapus.

## Tindak lanjut di worktree

- **Penyimpanan dan akses (01–03):** kategori dan transaksi disimpan di PostgreSQL. REST, sinkronisasi, transaksi berulang, dan rekonsiliasi menggunakan [penulis buku kas yang sama](../apps/api/src/db/ledger.ts). API kantong memeriksa identitas anggota dan perannya sebelum membaca riwayat atau mengubah dana. Anggaran, target, templat, dan aturan berulang tidak menggunakan memori proses sebagai sumber data.
- **Kunci aplikasi (04):** kesalahan verifikasi tidak membuka layar; PIN alternatif hanya tersedia setelah dibuat pengguna. Uji Face ID/Touch ID, dialog sistem, pergantian aplikasi, dan pemulihan akses pada perangkat fisik masih diperlukan.
- **Saldo, mutasi bank, dan CSV (05–07):** pengembalian dibatasi pada debit kantong yang tercatat. Mutasi ambigu tetap di kotak masuk. Transfer CSV mempertahankan dompet asal/tujuan, biaya, waktu, dan catatan berkutip; baris dengan nama dompet ambigu atau tidak dikenal ditolak.
- **Sinkronisasi (08):** katalog dompet dan kategori tidak bergantung pada antrean transaksi. [Tes SQLite dan PostgreSQL](../apps/mobile/src/db/sqlite.test.js) memeriksa pemulihan dompet kosong, pengarsipan, pengembalian alokasi lintas perangkat simulasi, dan pengiriman transaksi lain ketika satu struk gagal.
- **Temuan tambahan:** pilihan tanggal dan kantong disimpan saat mengedit. Berkas ekspor ditempatkan di cache per pengguna dan dibersihkan setelah dialog berbagi selesai. Undangan lintas perangkat tidak lagi ditawarkan di UI lokal. PostgreSQL tidak memublikasikan port ke host dan struk Compose menggunakan volume persisten.

Verifikasi setelah perbaikan: **111 tes lulus, 0 gagal**, mencakup PostgreSQL sementara dan SQLite di memori. Typecheck ketiga workspace, build API dan migrator, ekspor Expo untuk iOS/Android, dan validasi konfigurasi Compose lulus. Dialog berbagi diuji dengan pengganti modul native; belum diuji pada perangkat fisik.

Perubahan ini tidak memperbaiki data historis secara otomatis. Sebelum rilis, ikuti [langkah pembaruan](../README.md#sebelum-memperbarui-instalasi-lama), bandingkan catatan lama dengan cadangan, dan uji pemulihan PostgreSQL beserta volume struk.
